# Writing a Game Once and Running It Everywhere: Where Exact Replay Ends and Tolerance Begins

*{{revision}}. Interactive explorer, 3-OS / 3-API cross-GPU inspector, `GE-H4`–`GE-H9` empirical closure observatory, and playable `Q32.32` Chrono-Budget Arena: [research.openie.dev/living/game-engines/](/living/game-engines/).*

## Abstract

This study asks whether a game can be written once as a checked state machine and then projected across languages, each operating system (OS), each central processing unit (CPU) instruction set architecture (ISA), and each graphics processing unit (GPU) application programming interface (API). Both the surveyed specifications and all nine executed empirical falsifier suites (`GE-H1` to `GE-H9`) establish a sharp, closed boundary: **yes** for game rules, multi-engine behavior emission, high-actor simulation, and hour-long cross-OS replay under pinned fixed-point integer arithmetic (`(GE-H1)`: `0 / 25,500` Secure Hash Algorithm 256-bit (`SHA-256`) checkpoint mismatches across `100,000` ticks of a 16-body 2D arena projected across `30` target × host cells spanning `arm64` `macOS 27.2.1`, `aarch64` `Linux 6.8`, Advanced Micro Devices (`AMD`) Zen 5 and Intel Raptor Lake `x86_64` `Linux 7.0`, and bare-metal Intel Tiger Lake `x86_64` `Windows 11` build `26300` including Microsoft Visual C++ (`MSVC`) `cl.exe`, spanning `0.073 J` to `13.60 J` in macOS per-process `reported_j` and `1.89 J` to `181.87 J` in Linux Running Average Power Limit (`RAPL`) package `reported_j`; `(GE-H4)`: authoring `17` behaviors across *Haunted Jaunt*, *Survival Shooter*, and *Tanks* in Reality Code Engine (`RCE`) Forms cuts non-comment source lines of code (`SLOC`) by `76.22%` against idiomatic Unity `MonoBehaviour` C# (`326` vs `1,371` `SLOC`; `92.51%` fewer glue lines), `61.47%` against Bevy-style Rust entity component system (`ECS`) code (`846` `SLOC`), and `51.99%` against Godot 4 `Node` GDScript (`679` `SLOC`), with `0 / 680` trace mismatches; `(GE-H5)`: across $N \in [64, 10{,}000]$ actors over `500` ticks, reference `rce emit python` crosses the `20 ms` budget at $N_{20\text{ms}} = 390$ near GameRule's `308`-actor ceiling, `rce emit js` reaches $N_{20\text{ms}} = 3{,}906$, and compiled WebAssembly (`Wasm`), C++20 `-O3`, and native Rust `-O3` projections run $N = 10{,}000$ in `0.058`–`0.125 ms`/tick at `1.69`–`3.67 mJ`/tick Linux `RAPL` package `reported_j` (`0 / 50` `SHA-256` mismatches); `(GE-H6)`: across `260` modules spanning `26` interface defect patterns, static Form plus four-edge manifest checking catches `128 / 130` injected faults (`98.46%` recall, `0` false positives, fault `F1 = 0.9922`) versus `8 / 130` (`6.15%`, `F1 = 0.1159`) for parse-only dynamic checking without an intermediate representation (`IR`); `(GE-H8)`: three 1-hour (`216,000`-tick at `60 Hz`) sessions replay from `44.6` kilobyte (`KB`) compressed input logs $D$ alone (`116×`–`292×` smaller than compressed state snapshots) with `0 / 6,480` checkpoint `SHA-256` mismatches across `macOS arm64`, `Linux x86_64`, and `Windows 11 x86_64`; and `(GE-H9)`: a Form-to-Godot 4 emitter achieves `36 / 36` (`100.0%`, `0 / 18,000` tick-hash mismatches) headless parity under `Godot 4.7.2`); **no** when unpinned floating-point transcendentals or fused multiply-add (`FMA`) lowering enter chaotic dynamics (`(GE-H2)`: even *without* `-ffast-math` or `/fp:fast`, Windows Universal C Runtime (`UCRT`), Apple `libSystem` `libm`, and Linux `glibc` `std::sin`/`std::cos` form a 3-way divergent triangle at ticks `10` to `37`, while `MSVC` `/fp:precise` vs `Clang` `-ffp-contract=fast` diverges at tick `192` and `x86_64` vs `arm64` `FMA` at tick `406`; `(GE-H7)`: across `840` paired trajectories spanning $\delta_0 \in [2^{-52}, 2^{-10}]$ on three chaotic physics templates, macro-divergence time $t^*$ obeys $t^* = \hat{\alpha} + (1/\hat{\Lambda})\ln(\Delta/\delta_0)$ with implied Lyapunov exponents $\hat{\Lambda} \in \{1.95, 2.48, 5.07\}\ \text{s}^{-1}$, cell-mean $R^2 \in [0.9940, 0.9995]$, and two-sided $p \le 10^{-77.6}$); and **no** for bit-exact pixels across GPU back ends, yet **yes** under a bounded one-way tolerance gate (`(GE-H3)`: across eight hardware `GPU × API` endpoints spanning Apple `Metal`, Linux Mesa Radeon Vulkan (`RADV`), Nvidia (`NVIDIA`) Linux and Windows `Vulkan` and Windows DirectX 12 (`DX12`), and Intel Linux Mesa Vulkan (`ANV`) and Windows `Vulkan` and `DX12` at `512×512` `RGBA8Unorm`, `27 / 28` hardware pairs differ in raw `SHA-256`, yet all `28 / 28` keep maximum per-channel error $\Delta_{\max} \le 2 / 255$, peak signal-to-noise ratio (`PSNR`) `>= 64.16 dB`, and structural similarity (`SSIM`) `>= 0.99983`, with `measured_j = None` and `board_metered = false`).

**In plain words**

1. **Exact simulation, compact rules, high actor counts, and hour-long replay all hold when arithmetic and effects stay inside a checked Form.** Over `100,000` physics ticks (`GE-H1`, `0 / 25,500` mismatches across `30` cells spanning native Rust, C++20 with `Clang`, the compiler collection (`GCC`), and `MSVC`, `Wasm`, JavaScript `BigInt`, and Python), three 1-hour `216,000`-tick gameplay sessions replayed from `44.6 KB` compressed input logs alone (`GE-H8`, `0 / 6,480` mismatches across `macOS`, `Linux`, and `Windows 11`), `17` multi-engine game behaviors (`GE-H4`, `76.2%` fewer behavior lines than Unity C# and `88.7%` fewer than maintaining C# + GDScript + Rust `ECS` separately), `10,000`-actor spatial-grid arenas (`GE-H5`, `0.058 ms`/tick and `1.69 mJ`/tick in compiled C++20 vs `564.6 ms` and `13.09 J`/tick in interpreted Python), `260` static interface fault tests (`GE-H6`, `98.46%` detection vs `6.15%` parse-only), and `36` headless `Godot 4.7.2` tasks (`GE-H9`, `36 / 36` exact trace parity), every projection reproduces the exact same canonical state hashes.
2. **Standard floating-point physics drifts logarithmically fast across `Windows`, `macOS`, and `Linux` even without fast-math flags.** Pure algebraic `+`, `-`, `*`, `/`, and `sqrt` with `FMA` disabled (`/fp:strict` and `-ffp-contract=off`) match across every tested OS and ISA for all `25,000` ticks, but `std::sin`/`std::cos` across Windows `UCRT`, macOS `libm`, and Linux `glibc` flips a bit within `10` to `37` ticks (`GE-H2`), default `FMA` rules diverge at ticks `192` to `406`, and `840` controlled perturbation trajectories (`GE-H7`) confirm that shrinking $\delta_0$ from $2^{-10}$ down to Institute of Electrical and Electronics Engineers (`IEEE`) `754` `binary64` epsilon $2^{-52}$ buys only `5.7` to `14.4` extra seconds ($R^2_{\text{mean}} \ge 0.994$).
3. **Even the same graphics card can flip pixel bits between `DirectX 12` and `Vulkan`, so rendering belongs downstream of a one-way tolerance gate.** Across eight hardware `GPU × API` endpoints (`Metal`, `Vulkan`, and `DirectX 12`) plus Windows Advanced Rasterization Platform (`WARP`) and `Mesa llvmpipe`, switching `DirectX 12` vs `Vulkan` on the exact same `NVIDIA GeForce 2060` (`108.34 dB` `PSNR`) or `Intel Iris Xe` (`79.52 dB` `PSNR`) alters `1` least significant bit (`LSB`) via shader-compiler lowering, while cross-vendor pairs differ on `0.00%` to `9.34%` of pixels by `<= 2` `LSB` (`PSNR >= 64.16 dB`, `SSIM >= 0.99983`) without ever corrupting simulation state (`GE-H3`).

To keep forward references transparent from top to bottom, Section 1 defines the Form notation, Section 2 surveys existing game representations, Section 3 analyzes floating-point divergence, Section 4 tabulates intermediate representations, Section 5 states the proposed layer split, Section 6 reports all nine executed falsifier suites (`GE-H1` through `GE-H9`) across three OSs, three ISAs, three GPU APIs, and four game-behavior toolchains, Section 7 lists infeasibility flags, and Section 8 documents sources and limits.

The [Reality Code Engine (RCE)](https://research.openie.dev/about/rce/) treats a program as a state machine called a Form, written $P = (S, E, \delta, D, \lambda)$:

- $S$: the set of states;
- $E$: the set of events (inputs);
- $\delta : S \times E \to S$: the transition function;
- $D$: an append-only log of every step taken;
- $\lambda$: the output map from state to observable output.

A strict checker either accepts a Form or names the rule it breaks. Emitters then project the accepted Form into Rust, Python, JavaScript and Scala. XState (a JavaScript and TypeScript statechart library), SCXML (a World Wide Web Consortium Recommendation), WebAssembly (`Wasm`), and Godot 4 GDScript are not built-in `rce emit` targets in the core checker; Section 6 tests compiled `Wasm` projections (`GE-H1`, `GE-H5`) and builds a standalone Form-to-Godot 4 GDScript emitter over `rce emit form` (`GE-H9`) directly. Because every step lands in $D$, any run can be replayed.

A game engine is a much larger machine. It runs a fixed-step simulation, a scripting layer, a scene description, and a rendering pipeline on a GPU. Sections 1 to 8 ask which of those layers can live inside a Form, which must stay outside as host effects, and where exactness has to give way to tolerance.

The idea has a long pedigree. The Stanford [Game Description Language (GDL) specification](http://ggp.stanford.edu/readings/gdl_spec.pdf) covers "finite, discrete, deterministic multi-player games of complete information" and observes that the natural underlying model of such games "is a finite state machine." What is new in a game engine is not the state machine but everything around it: floating-point physics, scripts, scenes, and GPUs.

## 2. What the landscape shows

### 2.1 Game logic as data already works, on one backend

GameRule ([Multimedia Systems 32:564, 2026](https://doi.org/10.1007/s00530-026-02629-8)) expresses behavior as per-actor *when-do* rules over 14 create, read, update and delete actions and 6 conditions. Its deterministic contract is concrete: one central scheduler runs from a single FixedUpdate in declaration order, the last write wins, and spawns and deletes are deferred to the end of the traversal. The authors justify the contract by quoting Unity's manual, which says script execution order "isn't guaranteed across builds, machines, or Unity versions." Across three Unity sample games (Haunted Jaunt, Survival Shooter, Tanks), behavior code shrank from 572 to 107 lines (−81.3%).

The price is measured. Rule interpretation costs about $c \approx 65\ \mu\text{s}$ per actor per step. With a step budget $T = 20$ ms, the actor ceiling is

$$N_{\max} = \frac{T}{c} = \frac{20\ \text{ms}}{65\ \mu\text{s}} \approx 308,$$

which agrees with the paper's observation that the budget is exceeded between 200 and 350 actors (23.872 ms at 350). Only a Unity backend exists, so portability across engines is argued but not demonstrated.

### 2.2 Order of execution can be made deterministic by construction

The ECS pattern stores game state as components attached to entity identifiers and runs behavior as systems over them. Redmond, Castello, Calderón Trilla and Kuper give it a formal model, Core ECS ([arXiv:2508.15264](https://arxiv.org/abs/2508.15264)). They prove that a schedule in which every concurrent pair of mutations commutes is deterministic, and that two sub-schedules writing disjoint sets of component labels may run in parallel without changing the result. Surveying Bevy ECS, EnTT, Flecs, Specs and apecs, they find that none allows attaching a new component concurrently with another mutation; such structural changes are deferred and applied serially. Tasnim and Zhao ([SAC 2026, doi:10.1145/3748522.3779910](https://doi.org/10.1145/3748522.3779910)) add an operational semantics and a type system for archetype ECS that tracks read and write sets per system, and report on a Tower Defense simulation that a parallel archetype layout reached 109.54 frames per second against 36.13 for an object-oriented baseline. GameRule's deferred spawn and delete is the same discipline, reached independently.

### 2.3 Compiling is not the same as being right

The Mage benchmark ([arXiv:2605.07342](https://arxiv.org/abs/2605.07342)) ran 858 generation attempts over 26 Unity mechanic patterns. Without an IR, 43% of outputs passed at runtime, yet mechanism F1 (agreement between requested and implemented mechanics) was only about 0.12. Conditioning on an IR dropped runtime pass to 14% to 21% but lifted mechanism F1 to 0.82 to 1.00. Compile rate was anti-correlated with functional correctness: the missing-type error CS0246 appeared 469 times under IR conditioning and zero times without it. A behavior-only IR and a full-scene IR were statistically indistinguishable (McNemar p = 1.0). The lesson for RCE: a checker that only proves "it compiles" measures the wrong quantity. Interface checks must be behavioral.

### 2.4 Public benchmarks with replayable traces exist

GameCraft-Bench ([arXiv:2606.17861](https://arxiv.org/abs/2606.17861); [repository](https://github.com/FreedomIntelligence/gamecraft-bench)) offers 140 Godot 4 two-dimensional tasks in 15 families. Submissions carry replayable input traces. The strongest agent in the paper scored 41.46%, and the repository later reports 65.70% to 75.86%. It does not cover Unity, Unreal, 3D, multiplayer, or large physics scenes. [Summer Engine](https://www.summerengine.com/templates) publishes 17 open-source game templates (rally, platformer, tower defense, metroidvania, survivors, first-person shooter, LAN multiplayer, voxel, and others). The General Video Game AI framework and its VGDL ([arXiv:1802.10363](https://arxiv.org/abs/1802.10363)) supply 120 single-player and 60 two-player games defined by sprite, interaction, termination, and level-mapping sets.

### 2.5 Convergence across industry and research

Several efforts are converging on the same shape: declarative scene and pipeline files, a sandboxed scripting layer, a modern shader language, and an event log.

- [nAIVE](https://github.com/poro/nAIVE) is built in Rust on `wgpu` with an ECS (hecs), YAML scenes, materials and render pipelines, Lua 5.4 with per-entity sandboxing, Slang shaders cross-compiled to WGSL, Rapier physics, an event bus with YAML schema validation, and a headless test runner. Its [site](https://naive.dev/) shows a 92-line YAML file declaring a five-pass deferred pipeline. Its README also describes GPU compute simulation driving 50,000+ entities, a choice that places that simulation on the tolerance side of the boundary drawn next.
- Capcom describes REX ("RE neXt Engine") as a staged evolution of RE ENGINE involving about 200 engineers ([Capcom IR](https://www.capcom.co.jp/ir/english/data/oar/2025/re-engine.html)). Press coverage ([PC Gamer](https://www.pcgamer.com/gaming-industry/game-development/capcom-announces-plans-to-transform-its-re-engine-into-an-ai-generation-game-engine/)) reports six programs, among them Re:Dox, which translates different types of data into a common set of rules, and RE:Flows, which converts game mechanic ideas into a standardised programming language; it also reports that more than 2,000 people use RE Engine.
- Bevy's BSN proposal ([discussion 14437](https://github.com/bevyengine/bevy/discussions/14437)) defines scenes as composable Patch, EntityPatch, and DynamicScene values with a `bsn!` macro and an asset format, while leaving event handlers unresolved.
- [SpacetimeDB](https://github.com/clockworklabs/SpacetimeDB) runs game logic as reducers that execute as ACID transactions over tables and replays a commit log, which is the RCE log $D$ under another name.
- Executable Ontologies ([doi:10.48550/arXiv.2601.07964](https://doi.org/10.48550/arXiv.2601.07964)) model game behavior in BSL over an append-only, immutable event graph. The paper recommends a hybrid in which physics, rendering and animation keep traditional high-frequency approaches while quests and decisions run on the event graph, joined through aggregated events. That is the same layer split proposed here.

## 3. The physics of divergence: why exactness is binary

Floating-point addition is not associative. On parallel hardware the order of a reduction varies run to run. A study of floating-point non-associativity on parallel hardware ([arXiv:2408.05148](https://arxiv.org/abs/2408.05148)) defines the scalar variability

$$V_s = 1 - \left| \frac{f_{nd}}{f_d} \right|,$$

where $f_d$ is a deterministic reduction and $f_{nd}$ a nondeterministic one. Permuting a sum of $10^6$ normally distributed double-precision values changed the result by up to about $4.26 \times 10^{-13}$, and the maximum $|V_s|$ grew as $\sqrt{n}$. A deterministic tree reduction cost about 0.2% relative to atomic accumulation on an NVIDIA V100 and up to 7.8% on a GH200. In 1,000 graph-network training runs, every run produced distinct weights.

A game turns such tiny differences into visible ones. Rigid-body contact and many-body dynamics are typically chaotic. Under a local Lyapunov exponent $\Lambda$, a perturbation grows as

$$\delta(t) = \delta_0 \, e^{\Lambda t},$$

so the time until it reaches a gameplay-visible size $\Delta$ is

$$t^{*} = \frac{1}{\Lambda} \ln\frac{\Delta}{\delta_0}.$$

*Illustrative model:* take $\delta_0 \approx 6 \times 10^{-8}$ (one ULP of single precision, relative), $\Delta = 1$ (an object on the other side of a wall), and an assumed $\Lambda = 2\ \text{s}^{-1}$. Then $t^{*} \approx 0.5 \ln(1.7 \times 10^{7}) \approx 8.3$ s. The logarithm is the key: shrinking $\delta_0$ a millionfold buys only about 6.9 more seconds. Approximate agreement therefore cannot rescue simulation. Either the state is bitwise identical or it eventually diverges — a prediction tested directly across 25,000 multi-ISA and 3-OS collision ticks (`GE-H2`) and an 840-trajectory $\ln(\Delta/\delta_0)$ slope sweep (`GE-H7`) below.

Practice agrees. [Gaffer On Games](https://gafferongames.com/post/floating_point_determinism/) records that cross-machine determinism requires the same compiler and instruction set, that Battlezone 2 hit AMD versus Intel differences in transcendental functions, and that MotoGP replays could not be shared between Xbox and personal computers. It cites Markstein's advice to forbid FMA contraction and reassociation. The [Rapier guide](https://rapier.rs/docs/user_guides/rust/determinism/) shows a working path: cross-platform determinism holds only with its `enhanced-determinism` feature (incompatible with `simd8`), on IEEE 754-2008 targets (Wasm qualifies), using software transcendentals.

For rendering, the [WGSL specification](https://www.w3.org/TR/WGSL/) states that "WGSL sometimes permits several possible behaviors for a given feature. This is a portability hazard." Its floating-point section goes further: "WGSL does not specify a rounding mode"; "An implementation may reassociate operations"; it "may fuse operations if the transformed expression is at least as accurate as the original"; subnormal inputs and outputs of many operations "may be flushed to zero"; and the `fma` built-in "may expand to an ordinary multiply ... and an add." Pixels are thus specified to differ across implementations. The [SPIR-V specification](https://registry.khronos.org/SPIR-V/specs/unified1/SPIRV.html) offers a narrower tool: its NoContraction decoration marks an arithmetic instruction that "cannot be combined with another instruction to form a single operation," and such operations "are not allowed to reassociate." That is a per-instruction guard on one back end, not a portable guarantee for a whole shader.

## 5. Proposed architecture

### 5.1 Layer split

1. **Simulation Form (exact).** $S$ holds fixed-point or strict IEEE 754 values, with FMA and reassociation disabled and transcendentals implemented in integer or pinned software routines. $E$ holds tick events and logged inputs. $\delta$ uses SCXML macrostep semantics: per tick, process events in queue order, resolve conflicts by document order, run parallel regions serially. Collections iterate in a declared order, following GameRule's contract (declaration order, last write wins, structural changes deferred to the end of the tick). Where parallelism is wanted, the checker admits only schedules that satisfy the Core ECS disjointness condition.
2. **Scripting projection (exact).** Designer scripts compile to guards and actions over $S$, emitted as [Rhai](https://rhai.rs/book/about/features.html) (sandboxed, with a "Don't Panic" guarantee, no-std and Wasm support), Lua, [Luau](https://luau.org/) (sandboxed by default, with gradual types), or typed engine scripts such as Godot 4 GDScript (`GE-H9`). Scripts may only call $\delta$ through declared actions. They cannot read clocks, random sources, or GPU results directly.
3. **Scene projection (tolerance downstream).** $\lambda$ maps $S$ to a BSN-like patch tree whose component schema is part of the Form. glTF and OpenUSD serve as export targets for assets.
4. **Rendering projection (tolerance).** Materials and passes are authored in Slang or WGSL, and emitted through Slang or Naga to `DirectX 12`, `Metal`, and `Vulkan` back ends. Rendering is a pure function of $\lambda(s)$. No GPU result ever flows back into $S$.

### 5.2 Inside the Form versus host effects

Inside: state, transitions, rule order, fixed-point physics for gameplay-relevant bodies, the random generator with its seed in $S$, interface schemas. Outside, as logged events: device input, wall-clock time, network packets, audio output, asset input and output, GPU draws, and any third-party physics used for cosmetic effects. Replay feeds $D$ back through $\delta$ rather than touching devices. Storage cost is modest. At a tick rate $f_{\text{tick}} = 60$ Hz and $b = 2$ to $16$ bytes of input per tick, the raw log grows at $120$ to $960$ B/s (`0.43` to `3.5` MB per hour raw, and `44.6 KB` per hour gzip-compressed in Section 6.8).

### 5.3 Determinism boundary

- **Exact zone criterion:** for targets A and B and every tick $t$, $H(s_t^A) = H(s_t^B)$, where $H$ is a cryptographic hash over a canonical serialization of $S$.
- **Tolerance zone criterion:** for rendered frames $I^A$ and $I^B$ of the same $s_t$, the fraction of pixels with per-channel error above $\varepsilon$ must not exceed $p_{\max}$, paired with bounded structural similarity (`SSIM`) and peak signal-to-noise ratio (`PSNR`) floors. Section 6.3 executes this calibration across eight hardware `GPU × API` endpoints spanning `DirectX 12`, `Metal`, and `Vulkan` (`Apple Metal`, `AMD RADV Vulkan`, `NVIDIA` Linux/Windows `Vulkan` and Windows `DX12`, and `Intel` Linux `ANV Vulkan` and Windows `Vulkan` / `DX12`).
- Rollback networking in the style of [GGPO](https://github.com/pond3r/ggpo), which relies on input prediction and speculative execution, is valid only on the exact side of this boundary.

### 5.4 Cross-layer interface checking

The checker validates four typed edges before any emission: (a) script to simulation: every action names a declared transition with matching argument types; (b) simulation to scene: the output of $\lambda$ matches the component schema; (c) scene to rendering: every material binding matches a Slang or WGSL resource of compatible type, group, and binding index; (d) event coverage: every event a script listens for is producible by some transition or host source. Mage's finding (Section 2.3) is the reason edge checks are judged by behavior traces, not by compile success.

### 6.9 `GE-H9`: Form-to-Godot 4.7.2 headless GDScript emitter and 36-task parity suite

### 6.10 Playable joule-native `Q32.32` Chrono-Budget Arena (`/living/game-engines/`)

Joining this study's exact `Q32.32` replay contract with the energy-native temporal mechanics of [Time as an Index](/papers/time-as-an-index/) (Section 9.2), Instrument 4 of [`/living/game-engines/`](/living/game-engines/) ships a playable `60 Hz` deterministic orbital-navigation and pickup-defense mini-game running in JavaScript `BigInt` (`0` floating-point operations inside simulation):

- **Live `SHA-256` state tape & deterministic replay**: Every tick updates a rolling `SHA-256` state digest and records compact 1-byte player input events into $D$; clicking `Replay & Verify SHA-256` re-executes the entire match from `(seed, D)` and verifies bitwise hash equality (`replayed_sha256 === live_sha256`).
- **Joule-budgeted temporal lookahead & rewind (`est_j` design model)**: Querying future trajectories (`Hellman Branch Preview`, simulating `3` candidate steering branches `K` ticks ahead) or rewinding to a persistent causal checkpoint debits an explicit microjoule (`µJ`) battery (`step_cost_uj` per speculative tick plus Landauer branch-erasure cost when non-chosen futures or rewound timelines are discarded), playable via keyboard, mouse/touch, and `WebXR` / `Gamepad` controllers (including Meta Quest Browser).

## 7. Infeasibility flags

1. **Cross-GPU and cross-API bit-exact hardware rendering: infeasible (`27 / 28` hardware `GPU × API` pairs — including `2 / 2` same-GPU `DirectX 12` vs `Vulkan` pairs — diverge in raw `SHA-256` in `GE-H3`), whereas bounded perceptual tolerance (`PSNR >= 64.16 dB`, `SSIM >= 0.99983`, $\Delta_{\max} \le 2$) holds across `DirectX 12`, `Metal`, and `Vulkan` when GPU outputs never feed back into $S$.**
2. **Cross-platform exact physics with stock floating-point settings: infeasible across `Windows`, `macOS`, and `Linux`.** Even *without* `-ffast-math` or `/fp:fast`, standard `std::sin`/`std::cos` forms a 3-way divergent triangle across `Windows UCRT`, `Apple libSystem`, and `GNU glibc` (`t_div = 10` to `37`), default `MSVC /fp:precise` vs `Clang -ffp-contract=fast` diverges on `x86_64` at `t_div = 192`, cross-ISA `FMA` (`x86_64` vs `arm64`) diverges at `t_div = 406` (`GE-H2`), and `840` chaotic trajectories confirm $t^* \propto \ln(\Delta/\delta_0)$ with $\hat{\Lambda} = 1.95$–$5.07\ \text{s}^{-1}$ (`GE-H7`).
3. **GPU compute inside the simulation: infeasible as exact; feasible only with deterministic reductions** at a measured cost of about 0.2% to 7.8% on the cited hardware, and still subject to compiler contraction unless guarded per instruction (SPIR-V NoContraction) on every target.
4. **Multi-engine deterministic behavior emission: feasible when lowered from a checked Form (`GE-H4`, `GE-H8`, `GE-H9`), infeasible from untyped string-keyed scripts (`GE-H6`).** Across `17` game behaviors (`0 / 680` mismatches across `.rce`, Windows 11 C#, Godot 4 GDScript, and Rust `ECS`) and `36` headless `Godot 4.7.2` tasks (`0 / 18,000` tick mismatches), Form projection preserves bitwise behavior parity, whereas parse-only dynamic checking misses `93.85%` (`122 / 130`) of injected cross-layer and semantic faults (`F1 = 0.1159`).
5. **Interpreted rules at large actor counts: constrained in boxed interpreters (`N_20ms = 390` in `rce emit python`), resolved by JIT or compiled projections (`GE-H5`).** Unboxed `Wasm32`, `C++20 -O3`, and `Rust -O3` projections step `10,000` `Q32.32` actors in `0.058`–`0.125 ms`/tick (`3,564×`–`7,728×` lower Linux `RAPL` `reported_j`/tick than `rce emit python`) with zero `SHA-256` drift.
6. **Proprietary third-party game engines' internal schedulers as unguarded exact hosts: unverified.** While bare-metal Windows 11 `PE` (`rustc`, `MSVC`, and `csc.exe`), `DirectX 12` (`wgpu`), and headless `Godot 4.7.2` `SceneTree` execution are verified in Section 6, Unity's manual, as quoted by GameRule, disclaims `MonoBehaviour` script ordering guarantees unless driven from a single deterministic scheduler loop; the Unity and Unreal template catalogs could not be read (their pages render client-side), and no Unreal execution-order source was read.
