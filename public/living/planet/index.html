Two branches of one exact world

A small planet, stored only as a seed and a log of edits. Branch A and branch B share both. Change one cell in B and watch the difference spread through the weather. Because every step is integer arithmetic, any difference between the branches was caused by the edit and by nothing else.

Companion figure to Section 3 of A Planet You Can Take Apart. Tests and results: docs/planet/ in the repository.

What this is. A toy: a 192 × 96 strip of a planet (east and west wrap; the top and bottom rows are the poles) with sun, heat, wind, vapour, rain, rivers and erosion, all in 32-bit integers. It is a simulation, not a climate model, and its numbers are not Earth's. Element fractions come from mineral formulae and standard atomic weights; the mixes of minerals in each rock are illustrative. The GPU check runs on this device only; it says nothing about other devices.

      Does this GPU generate the same planet?

      run on this device

      The generator is written twice: in JavaScript (the reference) and in the WebGPU Shading Language (WGSL), using 32-bit integers only. WGSL specifies that integer arithmetic wraps modulo 232, so every GPU should produce the same cells. This check generates four worlds of 1024 × 512 cells on your GPU and compares every cell with the reference. It then changes one bit of one constant in the shader, to show the comparison would notice.

      planet-03

      What the figure shows

      The world is a function and a log. Neither map is stored. Each is the seed run forward with its edit log. "Replay" rebuilds A from nothing, twice: once in JavaScript and once in a separate implementation of the same rules written in Rust and compiled to WebAssembly. Both must reproduce the live state hash exactly.

      Matter is conserved. Digging moves ground into your inventory and raising moves it back. Water moves between ground, air and inventory. The totals under State never change, and an edit that would make anything negative is refused before it enters the log.

      The butterfly effect is attributable. With exact arithmetic, two branches with the same log stay identical forever, so the whole difference map is the consequence of your edit. With floating point that differs between machines, the same map would mix your cause with rounding noise.
